---
title: Easy to copy is not the same as obvious.
date: 2026-11-14
tag: LAW
---
Something that took me months to figure out, Claude Code can rebuild in an afternoon. I watched it happen in my own lab: a consolidated text of UU ITE, both amendments merged, every later revocation noted, assembled in about 45 minutes. So I started asking the question every builder asks now. If anyone can duplicate anything, what is left to protect?

Patent law has a clear answer, and it is not the one I expected. It never asks how hard something was to build.

Under UU 13/2016 tentang Paten, as last amended by UU 65/2024, a patent needs three things (Pasal 3): the invention must be new, it must involve an inventive step, and it must be industrially applicable. "New" means it was not disclosed anywhere before the filing date (Pasal 5). "Inventive step" means that to a person skilled in the field it was "tidak dapat diduga sebelumnya" at the time of filing (Pasal 7). Effort is not in the test. Months of work can still be obvious. A five-minute idea can still be inventive.

The trap is hindsight. Claude rebuilt my consolidation fast because I had already decided what to build: keep the text and its legal status as two separate layers, check every change against a ledger, and never trust a database summary of a court ruling. Being easy to rebuild *after* you have seen the answer says nothing about whether the answer was obvious *before*. Examiners are trained to discount exactly that.

Still, there is a real pressure point here. Pasal 7 ayat (2) judges skill "pada saat Permohonan diajukan". If the ordinary skilled person in 2026 works with an AI coding agent, then what counts as "not obvious" moves up with them. That debate is open everywhere, not just in Indonesia.

Two more things surprised me.

First, easy copying is the whole reason patents exist. The deal is disclosure in exchange for exclusivity: you explain how it works, the state stops others from using it for a while. Rebuilding a patented invention with Claude Code is still infringement. Speed is not a defence.

Second, for people like me, software and legal methods, the real wall is not novelty. It is Pasal 4. An invention does not include methods for mental activity or business, computer programs (except a "computer-implemented invention"), or the presentation of information. A clever way to organise regulations probably falls under more than one of those. Copyright protects my code as written, but not the idea behind it. Anyone can write it again in their own words.

And the inventor has to be a person: "seorang atau beberapa orang" (Pasal 1). The inventive part has to come from the human, not the tool.

So if code is cheap, where does the value go? I keep coming back to a note I wrote earlier, [Law is a database problem.](/beyond-statutes/law-is-a-database-problem/) In that same 45-minute build, the parts no tool could copy were judgement calls. Deciding what an ambiguous revocation clause really means. Noticing that a database had quoted what the applicants *asked for* as if it were the Court's ruling. Finding the two laws the database forgot to link.

The code gets cheaper every month. Being right, and being trusted to stay right, does not.
